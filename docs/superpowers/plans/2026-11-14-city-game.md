# City Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the vocab app's three-screen flow with a small emoji-tile city game. You walk to four places, and each place plays its lesson as a conversation with a host, then a quiz for coins and a passport stamp.

**Architecture:** Pure, React-free game logic in `src/game/` (map, movement, pathfinding, state reducer, save/load), each with unit tests. React screens live in `src/components/game/`: `StartScreen`, `CityScreen`, `PlaceScreen`, `Celebration`. The lesson pipeline (`requestLesson`, the Edge Function and all checks) is reused unchanged, apart from one prompt rule.

**Tech Stack:** Existing app: Vite + React 19 + TypeScript + Tailwind + shadcn/ui, Vitest + Testing Library. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-city-game-design.md`. Builds on `docs/superpowers/specs/2026-11-14-vocab-conversations-design.md`.

## Global Constraints

- **All UI text in Vietnamese.** Fixed copy from the spec: "Bắt đầu", "Chơi tiếp", "Chơi mới", "Đi đến một địa điểm để bắt đầu", "Rời đi", "Bắt đầu hội thoại", "Đang chuẩn bị…", "Tiếp ▸", "Cùng xem lại các từ nhé!", "Làm bài kiểm tra", "Đúng rồi!", "Chưa đúng.", "Về thành phố", "Bạn đã hoàn thành cấp N!", "Chơi lại cấp N", "Lên cấp N+1", "Tiếp tục dạo phố", "Thử lại", "Xem bài mẫu", "Chọn lại từ", "Bài mẫu".
- **Four places = the four `SCENARIOS`** (`cafe`, `supermarket`, `taxi`, `clinic`). Place ids are scenario ids.
- **City:** one screen, about 10 columns × 8 rows. Every door reachable in **≤ 12 steps** from the start tile. Slide animation **~120 ms per tile**.
- **Coins:** **+10 per right quiz answer**, credited when answered. **Stamp:** awarded on finishing the quiz, whatever the score.
- **Level** is fixed for the round. Level up is unavailable at level 3.
- **All emoji come from one lookup module** (`src/game/art.ts`).
- **Saved progress:** `localStorage` key `vocab-city-v1`. Every access is wrapped in try/catch, and the game works without it.
- **Lesson pipeline unchanged** apart from the two-speaker, host-first prompt rule. All existing `supabase/functions/_shared` tests keep passing.
- Work on branch `build/city-game`. Before merging, fetch `origin/main` and merge in any Lovable commits.

## Review Focus

1. **Arrow keys or new taps during a tap-walk.** Expect the current walk to cancel, and the new input to start from the character's current tile: no jumps, no two walks at once. Test in Task 9.
2. **Typing in a text box with arrow keys or WASD** (e.g., typing "sad" in a future input on the city screen), or keys pressed inside a place. Expect the city character not to move. Test in Task 9.
3. **Old or corrupt saved data** (unknown place id in stamps, level 7, coins `NaN`, non-JSON). Expect a fresh game, not a crash. Test in Task 5.
4. **An AI lesson with a third speaker, or where the customer speaks first** (the prompt asks, but the checks don't enforce it). Expect every line to still render: the first speaker on the host side, all others on the player side. Test in Task 7.
5. **Replaying a place after the round is complete,** or replaying an already-stamped place as the "fourth" finish. Expect the celebration not to pop up again unasked, and stamps to stay at four. Test in Task 4.

  ```ts
  export type Tile = 'road' | 'grass' | 'tree' | 'water' | 'building' | 'door'
  export interface Door { placeId: string; pos: Pos; outside: Pos }
  export interface CityMap { width: number; height: number; tiles: Tile[][]; placeAt: (string | null)[][]; doors: Door[]; start: Pos }
  export function parseMap(rows: string[], placeLetters: Record<string, string>): CityMap

  export const CITY: CityMap
  export function inBounds(map: CityMap, p: Pos): boolean
  ```

Map legend for `CITY_ROWS`: `.` road, `,` grass, `^` tree, `~` water, `@` start (a road tile). Building tiles use an uppercase letter and the door the same letter in lowercase: `C`/`c` café, `S`/`s` supermarket, `T`/`t` taxi, `K`/`k` clinic (`placeLetters = { c: 'cafe', s: 'supermarket', t: 'taxi', k: 'clinic' }`). `placeAt[y][x]` holds the place id for that place's building and door tiles, and null elsewhere. A door's `outside` is its first walkable non-door neighbour, checked in the order down, up, left, right. `parseMap` throws if rows have different lengths, a letter is unknown, there isn't exactly one `@`, or a place lacks exactly one door.

### Task 4: Game state reducer

**Files:**

**Interfaces:**
- Consumes: `Level` from `@shared/types.ts`, `SCENARIOS`.
- Produces:
  ```ts
  export const COINS_PER_CORRECT = 10
  export const PLACE_IDS: string[]          // SCENARIOS ids
  export interface GameState {
    level: Level; stamps: string[]; coins: number
    complete: boolean; celebrationOpen: boolean
    lastWords: Record<string, string[]>
  }
  export type GameAction =
    | { type: 'earnCoins'; amount: number }
    | { type: 'finishPlace'; placeId: string }
    | { type: 'rememberWords'; placeId: string; words: string[] }
    | { type: 'openCelebration' } | { type: 'dismissCelebration' }
    | { type: 'playAgain' } | { type: 'levelUp' }

  export function gameReducer(state: GameState, action: GameAction): GameState
  export function canLevelUp(state: GameState): boolean
  ```

Rules: `finishPlace` adds the stamp once (keeping `PLACE_IDS` order). When stamps first reach all four, it sets `complete: true, celebrationOpen: true`. Unknown place ids are ignored.
